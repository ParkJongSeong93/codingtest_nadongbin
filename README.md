# 알고리즘 유형

### 그리디 알고리즘

- 지금 당장 좋은 것만 고르는 방법
- ex) 거스름돈 문제 → 가장 큰 화폐단위부터 계산하는 방식
- 해법을 찾고 그 해법이 정당한지 검토 필요

### 구현

- 머릿속에 있는 알고리즘을 소스코드로 바꾸는 과정
- 완전탐색 - 모든 경우의 수를 다 계산하는 방식
- 시뮬레이션 - 문제에서 제시한 알고리즘을 한 단계씩 수행
- 크기가 1,000만 이상인 리스트는 메모리 부족의 가능성
- 1초에 2,000만 번의 연산을 수행한다고 가정

### **BFS/DFS**

- DFS - 깊이 우선 탐색, 그래프에서 깊은 부분을 우선적으로 탐색
    - 스택 자료구조 사용
        1. 탐색 시작 노드를 스택에 삽입하고 방문 처리
        2. 스택의 최상단 노드에 방문하지 않은 인접 노드가 있다면 스택에 넣고 방문 처리,
        모두 방문 시 스택에서 최상단 노드 pop
        3. 2번의 과정을 더 이상 수행하지 못할 때까지 반복
- BFS - 너비 우선 탐색, 가까운 노드부터 탐색
    - 큐 자료구조 사용
        1. 탐색 시작 노드를 큐에 삽입하고 방문 처리
        2. 큐에서 노드를 꺼내고 방문하지 않은 인접 노드를 모두 큐에 삽입, 방문 처리
        3. 2번의 과정을 더 이상 수행하지 못할 때까지 반복

- 스택 - 선입후출(First In Last Out)

```python
stack = []
stack.append(5)
stack.append(7)
stack.pop()
```

- 큐 - 선입선출(First In First Out)

```python
from collections import deque
queue = deque()
queue.append(5)
queue.popleft()
```

- 인접 행렬 - 2차원 배열로 그래프의 연결 관계 표현(메모리 낭비, 속도 높음)
- 인접 리스트 - 리스트로 그래프의 연결 관계를 표현(메모리 좋음, 속도 낮음)

### **정렬**

- 선택 정렬 - 매번 가장 작은 것을 선택하고 앞으로, O(N^2)
- 삽입 정렬 - 배열의 두 번째 원소부터 맨 앞의 정렬된 리스트와 비교해서 넣어야할 위치에 삽입,
O(N^2), 만약 현재 데이터가 거의 정렬되어 있는 상태라면 최선의 경우 O(N)
- 퀵 정렬 - 피벗을 설정하고 피벗을 기준으로 더 작은 것들, 큰 것들을 나누고 그것을 반복하며 정렬,
평균적으로 O(N log N), 데이터가 이미 정렬된 경우 최악은 O(N^2)
- 계수 정렬 - 데이터의 최솟값부터 최댓값까지 담을 수 있는 배열을 만들고 데이터의 갯수를 저장, 그 후 배열의 원소들을 출력,
데이터 갯수가 N, 데이터 중 최댓값이 K일 때 O(N + K)

+)  파이썬의 sorted()의 경우, O(N log N)

### 이진 탐색

- 데이터가 정렬된 상태에서만 사용 가능
- O(log N)

```python
def binary_search(array, target, start, end):
    while start <= end:
        mid = (start + end) // 2
        if target == array[mid]:
            return mid
        elif target < array[mid]:
            end = mid - 1
        elif target > array[mid]:
            start = mid + 1
    return None

n, target = list(map(int, input().split()))
array = list(map(int, input().split()))

target_idx = binary_search(array, target, 0, len(array)-1)
if target_idx == None:
    print("없는 원소입니다")
else:
    print(f"target index: {target_idx + 1}")
```

### 다이나믹 프로그래밍(DP)

- 큰 문제를 작은 문제로 나누고 작은 문제에서 구한 정답이 큰 문제에서도 사용될 때 적용
- 탑다운 - 큰 문제를 해결하기 위해 작은 문제를 호출
- 바텀업 - 작은 문제부터 차근차근 답을 도출 (이것을 권장)

+) 메모이제이션은 탑다운에서 사용, 캐싱으로 생각하면 됨

### 최단 경로

- 다익스트라 알고리즘
    - 특정한 노드에서 출발하여 다른 노드로 가는 각각의 최단 경로를 구해주는 알고리즘
    - 그리디 알고리즘으로 분류됨
    - V는 노드의 갯수, E는 간선의 갯수 O(E log V)
        1. 출발 노드를 설정
        2. 최단 거리 테이블을 초기화
        3. 방문하지 않은 노드 중에서 최단 거리가 가장 짧은 노드를 선택
        4. 해당 노드를 거쳐 다른 노드로 가는 비용을 계산하여 최단 거리 테이블을 갱신
        5. 위 과정에서 3, 4번을 반복

- 플로이드 워셜 알고리즘
    - 모든 지점에서 다른 모든 지점까지의 최단 경로를 모두 구하는 경우에 사용
    - O(N^3)
    
    ex) 미래 도시 문제
    

- 노드의 개수가 적은 경우 플로이드 워셜 알고리즘 사용,
노드와 간선의 개수가 모두 많으면 우선순위 큐를 사용하는 다익스트라 알고리즘 사용

- 우선순위 큐
    - 우선순위가 가장 높은 데이터를 가장 먼저 삭제
    - 최소힙의 경우 값이 가장 낮은 데이터가 먼저 삭제 (파이썬에서 기본적으로 사용)
    - 최대힙의 경우 값이 가장 큰 데이터가 먼제 삭제

### 그래프 이론

- union-find 알고리즘
    1. union 연산을 확인하여 서로 연결된 두 노드 A, B를 확인한다
        1. A와 B의 루트 노드 A’, B’를 각각 찾는다
        2. A’를 B’의 부모 노드로 설정한다 (B’가 A’를 가리키도록 한다)
    2. 모든 union 연산을 처리할 때까지 1번 과정을 반복한다

- 크루스칼 알고리즘
    - 신장 트리 - 모든 노드를 포함하면서 사이클이 존재하지 않는 그래프
    - 크루스칼 알고리즘 - 최소 비용으로 만들 수 있는 신장 트리를 찾는 알고리즘
    - 그리디 알고리즘으로 분류됨
    - 간선의 개수가 E일 때, O(E log E)
        1. 간선 데이터를 비용에 따라 오름차순으로 정렬
        2. 간선을 하나씩 확인하며 현재의 간선이 사이클을 발생시키는지 확인
            1. 사이클이 발생하지 않는 경우 최소 신장 트리에 포함
            2. 사이클이 발생하는 경우 포함X
        3. 모든 간선에 대하여 2번의 과정을 반복

- 위상 정렬
    - 방향 그래프의 모든 노드를 방향성에 거스르지 않도록 순서대로 나열
    - ex) 선수과목을 고려한 학습 순서 설정
    - O(V + E)
        1. 진입차수가 0인 노드를 큐에 삽입
        2. 큐가 빌 때까지 다음의 과정을 반복
            1. 큐에서 원소를 꺼내 해당 노드에서 출발하는 간선을 그래프에서 제거
            2. 새롭게 진입차수가 0이 된 노드를 큐에 삽입
